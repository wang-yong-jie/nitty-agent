# 2026-10-09：可插拔 Skill 系统第一版

状态：已实现并通过离线回归；真实模型与浏览器效果尚未评估。完整设计：[skills-design.md](../skills-design.md)。
设计始于 2026-10-09，实现与验证完成于 2026-10-10。

## 背景与目标

用户希望自己的 Agent 处理复杂任务，并希望后续重大迭代都留下详细的设计思路、介绍和验证记录。
此前项目只有工具及附带 instructions，没有独立 Skill 目录、按需加载和激活状态。

本次把任务知识与执行能力分离：Skill 指导模型如何做，原有工具、Runtime、任务记忆和验收负责实际执行与结果。
同时建立文档索引、历史记录模板和 AGENTS.md 维护约定。

## 方案与关键取舍

- 采用 `SKILL.md` 基本格式，额外工具依赖放 `metadata.nitty-required-tools`，避免自定义一套完全不同的文档结构。
- 使用现有工具调用机制提供激活/资源读取/停用；不引入额外路由模型。先让模型看到简介，选择后提供全文。
- 活跃正文独立于普通历史，每轮重建，解决长任务历史裁剪后遗忘指导的问题。
- 激活与停用要求单独一轮，避免同批动作在模型尚未看到指导时执行。
- 激活按 Run 隔离；新任务重新选择，更新和禁用在下一 Run 生效。
- 采用包内全部文件哈希，恢复时同时核对来源、版本和内容。代价是发现时需要读取有界资源字节，未使用资源变化也会阻止恢复。
- 不自动执行脚本，不把任意工作目录加入可信来源；先维持明确、可追溯的本地边界。
- 不改 API 请求契约与前端生成类型，CLI/Web 共用 bootstrap；现有通用事件时间线可查看 Skill 事件。

## 使用方法

```powershell
conda run -n agent python -m pip install -r requirements.txt
conda run --no-capture-output -n agent python main.py --long-horizon --skill complex-task --chat
```

CLI 使用 `--skill` 为每个新任务显式选择，省略该参数则由模型根据简介选择；Web 中启用长任务模式后，可以在任务开头输入独立行：

```text
/skill complex-task
整理指定资料，生成结果文件，并核对数量和内容。
```

新增 `.agents/skills/<name>/SKILL.md` 后，新 Run 自动发现。需要跨项目使用时放用户目录或配置 `NITTY_SKILL_DIRS`。
禁用使用 `NITTY_DISABLED_SKILLS` JSON 数组。修改 `.env` 后重启服务。

## 兼容、迁移与恢复

没有可用 Skill 时沿用原有工具；直接构造 Agent 未传管理器时不启用新机制。
旧 checkpoint 缺少 `skills` 时按空状态读取，不迁移 SQLite，也不改变主 checkpoint schema_version。
新快照保存 Skill 来源/版本/哈希，包内容、来源、禁用或依赖变化时阻止恢复。
任务工作目录不自动成为 Skill 搜索路径；多行显式指令可通过 Web 或 Python API 使用，CLI 标准输入仍然是一行一次，使用 `--skill` 选择。

## 局限与后续

本次提供 Skill 基础设施，尚未接入 Playwriter/MCP。Skill 不会自动提供浏览器能力。
第一版只展示有界目录，不做向量检索；使用字符预算；引用资料是普通历史数据，裁剪后应按需重读。
脚本没有专门执行器，既有 Shell 的能力范围不因 Skill 读取边界而收窄。
尚未提供远程安装、管理界面和自动 Skill 效果评估；路径迁移需要恢复原位置或开始新任务。

下一步应单独设计浏览器连接适配器及其恢复验证，然后以真实复杂任务评估浏览器 Skill。
