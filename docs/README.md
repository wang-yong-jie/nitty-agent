## 维护方式

重大改动应同时更新当前设计和增加一份历史记录，使用 [记录模板](changes/TEMPLATE.md)。
说明为何修改、最终行为是什么、为何选择该方案、如何使用、数据与恢复受到什么影响、做过哪些验证以及尚未覆盖什么。
实施中先写明确的方案与验收目标，交付前用真实结果更新验证部分。不能用“测试通过”代替实际命令和范围说明。

架构或能力模块、持久化与恢复协议、用户操作流程属于重大改动。后续接入 Playwriter/MCP 时，应建立独立设计与记录，
并引用本次 Skill 的接口约定，不把浏览器接入混写成已由 Skill 提供的能力。
